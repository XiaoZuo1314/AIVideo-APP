## 1. 项目概述

### 1.1 项目定位

SaveAny 是一个**全栈视频下载 + AI 总结**的 Web 应用，中文名"万能视频下载器"。核心价值是：

- **一站式视频下载**：支持 1800+ 平台的视频解析与下载（YouTube、B 站、Twitter/X、Instagram、TikTok、抖音等）
- **AI 智能总结**：基于视频字幕，利用 DeepSeek 大模型生成结构化总结、思维导图、AI 问答
- **VIP 付费体系**：免费用户每日 3 次 AI 总结，VIP 用户无限使用

### 1.2 七大核心功能

| 序号 | 功能 | 说明 |
|:---:|------|------|
| 1 | 视频解析 | 输入 URL，返回视频元数据（标题、封面、时长、清晰度列表） |
| 2 | 视频下载 | 服务器下载后返回文件流，或提取直链供客户端下载 |
| 3 | 抖音专用解析 | 专门处理抖音短链接，获取无水印视频 |
| 4 | AI 视频总结 | 提取字幕 → 流式生成总结 + 思维导图 |
| 5 | AI 视频问答 | 基于字幕内容回答用户问题 |
| 6 | 用户认证 | 邮箱注册/登录，JWT 鉴权 |
| 7 | VIP 支付 | Stripe Checkout 支付，Webhook 自动激活 |

## 4. 数据库设计

### 4.1 数据库配置

- **引擎**: SQLite（文件路径 `backend/data/app.db`）
- **连接模式**: WAL (Write-Ahead Logging)，提升并发读写性能
- **外键约束**: 开启 (`PRAGMA foreign_keys=ON`)
- **ORM**: 无，使用原生 `sqlite3` 模块 + SQL 语句
- **连接管理**: 上下文管理器 `@contextmanager get_db()`，自动 commit/rollback/close

### 4.2 users 表

```sql
CREATE TABLE IF NOT EXISTS users (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    email           TEXT UNIQUE NOT NULL,           -- 登录邮箱（唯一索引）
    password_hash   TEXT NOT NULL,                  -- bcrypt 哈希后的密码
    is_vip          INTEGER DEFAULT 0,              -- VIP 标志（0 或 1）
    vip_expire_at   TEXT,                           -- VIP 到期时间（ISO 格式）
    daily_summary_count INTEGER DEFAULT 0,          -- 当日已用 AI 总结次数
    last_summary_date   TEXT,                       -- 上次总结日期（YYYY-MM-DD）
    created_at      TEXT DEFAULT (datetime('now')), -- 注册时间
    updated_at      TEXT DEFAULT (datetime('now'))  -- 最后更新时间
);

CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);
```

**关键字段说明**:
- `is_vip` + `vip_expire_at`：双重判断 VIP 状态，必须 `is_vip=1` 且 `vip_expire_at > 当前时间` 才算有效 VIP
- `daily_summary_count` + `last_summary_date`：配合 `FREE_DAILY_SUMMARY_LIMIT=3` 实现每日配额限制，跨日自动重置

### 4.3 orders 表

```sql
CREATE TABLE IF NOT EXISTS orders (
    id                      INTEGER PRIMARY KEY AUTOINCREMENT,
    order_no                TEXT UNIQUE NOT NULL,           -- 订单号（SA + 时间戳 + 用户ID + UUID8）
    user_id                 INTEGER NOT NULL,               -- 关联用户 ID
    amount                  INTEGER NOT NULL,               -- 金额（最小货币单位，990 = 9.90 CNY）
    currency                TEXT DEFAULT 'cny',             -- 货币代码
    status                  TEXT DEFAULT 'pending',         -- 状态：pending / paid
    plan_type               TEXT DEFAULT 'monthly',         -- 套餐类型：monthly / yearly
    stripe_session_id       TEXT UNIQUE,                    -- Stripe Checkout Session ID
    stripe_payment_intent_id TEXT,                          -- Stripe Payment Intent ID
    paid_at                 TEXT,                           -- 支付完成时间
    created_at              TEXT DEFAULT (datetime('now')), -- 创建时间
    updated_at              TEXT DEFAULT (datetime('now')), -- 更新时间
    FOREIGN KEY (user_id) REFERENCES users(id)
);

CREATE INDEX IF NOT EXISTS idx_orders_user_id ON orders(user_id);
CREATE INDEX IF NOT EXISTS idx_orders_order_no ON orders(order_no);
CREATE INDEX IF NOT EXISTS idx_orders_stripe_session_id ON orders(stripe_session_id);
```

**订单号生成规则**: `SA{YYYYMMDDHHmmss}{user_id:04d}{uuid_hex_8位}`
- 示例: `SA202605111430250001a1b2c3d4`

### 4.4 ER 关系图

```
users (1) ──────< (N) orders
  │                    │
  │ id (PK)           │ id (PK)
  │ email (UNIQUE)    │ order_no (UNIQUE)
  │ password_hash     │ user_id (FK → users.id)
  │ is_vip            │ amount, currency
  │ vip_expire_at     │ status (pending/paid)
  │ daily_summary_count│ plan_type
  │ last_summary_date │ stripe_session_id (UNIQUE)
  └───────────────────┘ stripe_payment_intent_id
                        paid_at
```

## 6. 核心业务流程

### 6.1 视频解析流程

```
用户输入 URL
    │
    ▼
┌─────────────────┐
│  is_douyin_url() │  判断是否为抖音链接
│  (域名匹配)      │
└────┬────────┬────┘
     │        │
   是│        │否
     ▼        ▼
┌─────────┐  ┌──────────────┐
│DouyinParser│ │VideoDownloader│
│  .parse()  │ │ .parse_video()│
└─────┬─────┘  └──────┬───────┘
      │               │
      ▼               ▼
  _resolve_redirect()  yt_dlp.extract_info()
  _extract_video_id()    │
  _fetch_item_info()     ▼
      │              _extract_formats()
      │              整理为统一格式
      ▼
  _build_result()
  (统一输出格式)
      │
      ▼
  run_in_executor()  ← 包装为异步，不阻塞事件循环
      │
      ▼
  返回 JSON { success: true, data: {...} }
```

**关键细节**:
- 抖音解析有 3 层降级策略: 公开 API → 分享页 HTML 解析 → WAF 挑战破解
- yt-dlp 解析后会自动整理格式列表（去重、排序、补充合并选项）
- 所有阻塞操作通过 `run_in_executor` 转为异步

### 6.2 视频下载流程

```
用户选择清晰度 + 点击下载
    │
    ▼
前端 POST /api/download { url, format_id }
    │
    ├── 抖音 → DouyinParser.download()
    │         │
    │         ▼
    │     _resolve_redirect()
    │     _extract_video_id()
    │     _fetch_item_info()
    │     _get_media_url()  ← playwm 替换为 play（去水印）
    │     _download_file()  ← 3次重试 + .part 临时文件
    │         │
    │         ▼
    │     返回 { filepath, filename, title, ext }
    │
    ├── 其他平台 → VideoDownloader.download_video()
    │              │
    │              ▼
    │          检查 ffmpeg → 无则降级 format_id
    │          yt_dlp.download()
    │          3步文件定位: 直接路径 → prepare_filename → 扫描目录
    │              │
    │              ▼
    │          返回 { filepath, filename, title, ext }
    │
    ▼
FileResponse(filepath, filename, media_type="application/octet-stream")
    │
    ▼
前端接收 blob → 创建 Object URL → <a> 标签触发浏览器下载
```

**文件清理策略**: 应用关闭时（lifespan shutdown），删除 `downloads/` 目录下所有文件

### 6.3 AI 总结流程

```
用户点击"AI 总结"
    │
    ▼
前端 POST /api/summarize { url, language }
    │
    ▼
检查权限 (_check_summary_permission)
    │
    ├── 未登录 → SSE event: error { need_login: true }
    ├── 超出配额 → SSE event: error { need_vip: true }
    └── 通过 → 继续
         │
         ▼
    字幕提取 (SubtitleExtractor.extract)
         │
         ├── B站 → _extract_bilibili()
         │        │
         │        ▼
         │    api.bilibili.com 获取 cid/aid
         │    dm/view API 获取字幕列表
         │    优先选择 zh/zh-Hans 字幕
         │    下载字幕 JSON → 解析为 segments
         │
         └── 其他平台 → yt-dlp 提取字幕
                      │
                      ▼
                  _pick_best_subtitle()  ← 优先级: zh-Hans > zh > zh-CN > en > ja > ko
                  优先级: 人工字幕 > 自动字幕
                      │
                      ▼
                  下载 VTT 文件 → _parse_vtt() 解析为 segments
         │
         ▼
    SSE event: subtitle { has_subtitle, language, segments, full_text }
         │
         ▼
    AI 总结生成 (VideoSummarizer.summarize_stream)
         │
         ▼
    构建 prompt → DeepSeek API (stream=True)
         │
         ▼

```

```javascript
export async function summarizeVideo(url, language, token, callbacks) {
  const headers = { 'Content-Type': 'application/json' }
  if (token) headers['Authorization'] = `Bearer ${token}`

  const response = await fetch('/api/summarize', {
    method: 'POST',
    headers,
    body: JSON.stringify({ url, language })
  })

  const reader = response.body.getReader()
  const decoder = new TextDecoder()
  let buffer = ''

  while (true) {
    const { done, value } = await reader.read()
    if (done) break

    buffer += decoder.decode(value, { stream: true })
    const lines = buffer.split('\n')
    buffer = lines.pop()  // 保留不完整的行

    for (const line of lines) {
      if (line.startsWith('event: ')) {
        currentEvent = line.slice(7).trim()
      } else if (line.startsWith('data: ')) {
        const data = line.slice(6)
        // 根据 currentEvent 调用对应回调
        if (currentEvent === 'subtitle') callbacks.onSubtitle(JSON.parse(data))
        if (currentEvent === 'summary') callbacks.onSummary(JSON.parse(data))
        if (currentEvent === 'mindmap') callbacks.onMindmap(JSON.parse(data))
        if (currentEvent === 'done') callbacks.onDone()
        if (currentEvent === 'error') callbacks.onError(JSON.parse(data))
      }
    }
  }
}
```

## 9. 关键设计模式与技巧

### 9.1 异步桥接模式

**问题**: yt-dlp、requests 等库是同步阻塞的，但 FastAPI 是异步框架。

**方案**: `asyncio.run_in_executor(None, blocking_func, args)`

```python
# 将阻塞操作放到默认线程池
loop = asyncio.get_event_loop()
result = await loop.run_in_executor(None, downloader.parse_video, url)
```

**影响**: 并发数受限于线程池大小（默认 `min(32, cpu_count+4)`）

### 9.2 单例懒初始化模式

**问题**: DeepSeek API Key 可能未配置，如果在启动时初始化会直接崩溃。

**方案**: 首次请求时才创建实例，后续复用。

```python
def _get_summarizer():
    if not hasattr(_get_summarizer, "_instance"):
        _get_summarizer._instance = VideoSummarizer()
    return _get_summarizer._instance
```

### 9.3 URL 路由分发模式

**问题**: 抖音链接的解析逻辑与 yt-dlp 完全不同，需要特殊处理。

**方案**: 在 API 层通过 URL 域名判断，分发到不同的解析器。

```python
if is_douyin_url(req.url):
    result = await loop.run_in_executor(None, douyin_parser.parse, req.url)
else:
    result = await loop.run_in_executor(None, downloader.parse_video, req.url)
```

### 9.4 SSE 流式传输模式

**问题**: AI 总结需要较长时间，用户体验差。

**方案**: 使用 Server-Sent Events 逐步推送结果。

```python
# 后端：生成器函数 + EventSourceResponse

        yield ServerSentEvent(event="summary", raw_data=json.dumps(token))

# 前端：fetch + ReadableStream 手动解析 SSE
const reader = response.body.getReader()
while (true) {
    const { done, value } = await reader.read()
    // 解析 event: 和 data: 行
}
```

### 9.5 幂等性保证模式

**问题**: Stripe Webhook 可能重复发送同一事件。

**方案**: 只处理 `status='pending'` 的订单，在同一事务中更新状态。

```python
def complete_order(session_id, payment_intent_id):
    with get_db() as conn:
        order = SELECT ... WHERE stripe_session_id = ? AND status = 'pending'
        if not order: return None  # 已处理或不存在，幂等返回
        # 更新订单状态 + 激活 VIP（在同一事务中）
```

### 9.6 重试 + 指数退避模式

**问题**: 网络请求可能临时失败。

**方案**: 最多重试 3 次，每次等待时间翻倍。

```python
for attempt in range(self.max_retries):
    try:
        resp = self.session.get(url, timeout=self.timeout)
        resp.raise_for_status()
        return resp.url
    except requests.RequestException as e:
        if attempt == self.max_retries - 1:
            raise
        time.sleep(1 * (2 ** attempt))  # 1s, 2s, 4s
```

### 9.7 临时文件原子写入模式

**问题**: 下载中断会产生不完整文件。

**方案**: 先写入 `.part` 临时文件，完成后原子重命名。

```python

        if chunk: f.write(chunk)

```

### 9.8 上下文管理器模式（数据库）

**问题**: 数据库连接需要确保关闭，异常时需要回滚。

**方案**: `@contextmanager` 封装连接生命周期。

```python
@contextmanager
def get_db():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
        conn.commit()
    except:
        conn.rollback()
        raise
    finally:
        conn.close()
```

### 10.2 可替换方案

| 原方案 | 替代方案 | 说明 |
|--------|----------|------|
| SQLite + 原生 SQL | PostgreSQL + SQLAlchemy | 生产环境推荐 |
| DeepSeek API | OpenAI / Claude / 本地模型 | 只需替换 base_url 和 model |
| Stripe | 支付宝/微信支付 | 国内场景更适合 |
| JWT + localStorage | Session + Cookie | 更安全但需要服务端状态 |
| bcrypt | argon2 | 更现代的密码哈希算法 |
| SSE | WebSocket | 需要双向通信时替换 |
| 单文件架构 | 分层架构 (service/repository/router) | 项目变大时重构 |

### 10.3 注意事项

1. **安全性**:
   - 生产环境必须修改 JWT_SECRET，使用强随机字符串
   - CORS 不要用 `allow_origins=["*"]`，指定具体域名
   - 缩略图代理接口存在 SSRF 风险，需限制可请求的域名
   - `.env` 文件不要提交到 Git

2. **性能**:
   - yt-dlp 是 CPU 密集型操作，高并发需要更多工作进程
   - 下载大文件时注意磁盘空间和内存
   - 可以引入 Redis 队列 + Celery 做异步任务

3. **部署**:
   - 需要 ffmpeg（可以使用 static-ffmpeg 自动下载）
   - SQLite 不适合多进程部署，换用 PostgreSQL
   - 下载目录需要定期清理或使用对象存储

4. **前端**:
   - SSE 消费使用原生 fetch，不要用 Axios（Axios 不支持 SSE）
   - 大文件下载使用 blob + Object URL，避免内存溢出
   - 思维导图组件 markmap 需要额外引入 CSS
